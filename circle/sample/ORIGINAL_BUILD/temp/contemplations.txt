we have input and output modes. input means we process real values from the adc, output means we  use internal values 

adc - will read the input at the adc, attenuates it, sends it to group a ( shader ) or b ( system )
bpm - will process the tapped in bpm value to randomize the value send to a / b 
trg - will check the adc for a thresshold and if triggered will randomize the value send to a / b
lfo - will use the bpm and a wavetable and wave selector and multiplier to read an output value for a / b
aud - will analyse ( windowed average ) the adc by applying a sensitivity to create 3-4 bands whom i can than map to a / b
    here some "magic" / questions: 
    - shall i enable just two bands each possible input?
    - shall i enable 4 in total to map them to my channels, like 3 for a and one for b or 2 a and 2 b
    - shall i enable the audio modes only for the shader ( bank a )  or also b?
    - shall i use an autodetect instead of assinging the audio mode and block every other adc channel like i do now?
    - shall i than rather assign the band output rather than hard wire the bands to the channels

tex - is for now an extramode where i can choose the displayed texture in my 8 tex bank rather than choosing them from the glsl code ( tex array ),
      this is evolved from the need to compose many textures in one shader or use a single shader and chose it directly with and input. 
frm - is a mode that enables the user to map the position in time of the glsl funcion via adc and not as usual by an internal continiuos time ( loop )
clk - is supposed to assign one of the b adc´s as an sense/trigger input for external clock. the bpm calculation machine uses for now
      the last actual source ( either the tab in or the clock in ) as base for the bpm driven modes
vid - will be hopefully the new mode: we will use adc´s to choose between videos ( 0 to 7 ) and frames ( 0 - 1023 or multibles )
      but we need to figure out how we assign the inputs and on what banks
