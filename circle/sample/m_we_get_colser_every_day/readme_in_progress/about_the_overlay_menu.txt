Overlay Model — Current Design
Atlas lookup
AtlasTileIndex names every cell in the fixed atlas.

const GLfloat g_atlasTileMap[ATLAS_TILE_COUNT][2];
returns the atlas origin:

g_atlasTileMap[tile][0]    // atlas x
g_atlasTileMap[tile][1]    // atlas y
The enum ordering provides the variable tile selections directly:

ATLAS_TILE_MODE_ADC + mode

ATLAS_TILE_LFO_WAVE_SINE + waveform

ATLAS_TILE_DIVIDER_1_64 + divider

ATLAS_TILE_NUMBER_0 + digit
Screen-position lookup
OverlayScreenCoordinates names every fixed overlay position.

const int g_menuCoordinates[MENU_COORD_COUNT][2];
returns the screen offset:

g_menuCoordinates[coordinate][0]    // screen x
g_menuCoordinates[coordinate][1]    // screen y
The four mode sectors are:

MENU_COORD_MODE_0    // -128, -128
MENU_COORD_MODE_1    //     0, -128
MENU_COORD_MODE_2    // -128,     0
MENU_COORD_MODE_3    //     0,     0
Every component belonging to one mode uses the same sector coordinate.

The five target-coordinate entries must appear in g_menuCoordinates before the arrow entries so the table remains aligned with OverlayScreenCoordinates.

Layers 1 and 2 share one mode dispatcher.

Layer 8 uses its own system dispatcher.

Mode Dispatcher
runTheModeDispatcher() receives the layer.

It uses that layer to select the corresponding four-entry block from centralModeBuffer:

layer 1:
    MODE_CH0
    MODE_CH1
    MODE_CH2
    MODE_CH3

layer 2:
    MODE_CH4
    MODE_CH5
    MODE_CH6
    MODE_CH7
It resolves four modes:

Q0
Q1
Q2
Q3
and associates them with:

MENU_COORD_MODE_0
MENU_COORD_MODE_1
MENU_COORD_MODE_2
MENU_COORD_MODE_3
The four sector relationships are fixed:

sector 0:
    channel/block entry 0
    Q0
    MENU_COORD_MODE_0

sector 1:
    channel/block entry 1
    Q1
    MENU_COORD_MODE_1

sector 2:
    channel/block entry 2
    Q2
    MENU_COORD_MODE_2

sector 3:
    channel/block entry 3
    Q3
    MENU_COORD_MODE_3
Each sector is then sent to the helper corresponding to its selected mode:

Overlay_ADC(channel, coordinate);

Overlay_BMP(channel, coordinate);
Overlay_LF0(channel, coordinate);
Overlay_LF1(channel, coordinate);

The established helper parameters are:

unsigned channel
unsigned coordinate

Per-Tile GL Input
Every component produced by a mode or system helper resolves to:

atlas x
atlas y
screen x
screen y
Resolution is:

atlas_x =
    g_atlasTileMap[atlasTile][0];

atlas_y =
    g_atlasTileMap[atlasTile][1];

screen_x =
    g_menuCoordinates[coordinate][0];

screen_y =
    g_menuCoordinates[coordinate][1];
These four resolved values are the complete per-tile CPU-to-GL information.

prepareModeOverlay()
prepareModeOverlay() is the common handoff used by the semantic helpers.

Its responsibility is:

receive one selected atlas tile and one selected screen coordinate;
resolve or accept the four required values;
provide those values to the overlay GL code.
Its inputs must represent:

atlas tile
screen coordinate
or their resolved equivalents:

atlas x
atlas y
screen x
screen y
The final choice between these two signatures belongs to the remaining GL-interface decision.

GL Interface Still to Be Defined
